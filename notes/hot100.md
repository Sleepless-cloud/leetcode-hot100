# 小技巧

**索引计算：**

很多算法中都涉及索引，我们可以把索引和元素对应起来，而不是和两元素的间隔对应起来。

比如[3,1,4,5]，我们默认3的索引是0，1的索引是1，4的索引是2，5的索引是3。

然后，如果涉及到range，如果我们想取到1这个数，那么我们就得把眼睛放在4上，因为得取“下一位”，所以我们找4对应的索引，发现是2，那么就应该取for i in range(2)。

就比如我们想让这个数组（长度为n）的前面一半元素和后面一半元素位置进行交换。那么我们可以使用：for i in range(？// 2)？

解答：若n = 4，那么我们要取到1这个数，那么由于range的性质，我们得着眼于4，4的索引是2，那么就得取到2，所以想到使用n // 2，但是如果n是单数呢？若n = 5，[3,1,4,5,9]。那么我们需要取1这个数，那么由于range的性质，我们也是着眼于4，4的索引是2，那么就得取到2。5 // 2就是2，所以没毛病，我们就用n // 2就行。

最终答案就是range(n // 2)。

**可以做一做力扣54.螺旋矩阵和48.旋转图像来巩固这一点。**

【9】438.找到字符串中所有字母异位词

滑动窗口。由于给出了p，知道其长度，也就知道了滑动窗口的长度。所以可以设一个left然后再设一个l，l是滑动窗口的长度。

遍历字符串，看滑动窗口中内容在排序好后是不是等于排序好的p即可。

**以上方法容易超出时间限制（得看运气），最好使用以下滑动窗口+计数的算法：**

```Plain Text
class Solution:
    def findAnagrams(self, s: str, p: str) -> List[int]:
        count_p = [0] * 26
        count_s = [0] * 26
        ans = []
        for char in p:
            index = ord(char) - ord('a')
            count_p[index] += 1
        left = 0
        right = len(p)
        for char in s[left:right]:
            index = ord(char) - ord('a')
            count_s[index] += 1
        right -= 1
        while right < len(s):
            if count_s == count_p:
                ans.append(left)
            right += 1
            count_s[ord(s[left]) - ord('a')] -= 1
            count_s[ord(s[right]) - ord('a')] += 1
            left += 1
        return ans
```

**对于以上代码，有一个错误**：count_s[ord(s[right]) - ord('a')] += 1这一行会越界，但是如果不进行这次循环，又无法判断count_s和count_p是否相等从而造成漏掉最后一个解。那怎么办呢？

可以只进行if count_s == count_p那一行嘛，之后的如果检测到right == len(s)那就直接break。改成：

```Python
class Solution:
    def findAnagrams(self, s: str, p: str) -> List[int]:
        count_p = [0] * 26
        count_s = [0] * 26
        ans = []
        for char in p:
            index = ord(char) - ord('a')
            count_p[index] += 1
        left = 0
        right = len(p)
        for char in s[left:right]:
            index = ord(char) - ord('a')
            count_s[index] += 1
        while right <= len(s):
            if count_s == count_p:
                ans.append(left)
            if right == len(s):
                break
            count_s[ord(s[left]) - ord('a')] -= 1
            count_s[ord(s[right]) - ord('a')] += 1
            right += 1
            left += 1
        return ans
```

- 最后一个字符已经匹配了，不需要任何操作。

- $dp[i][j] = dp[i-1][j-1]$

- **如果 ****`word1[i-1] != word2[j-1]`**：

- 我们需要从以下三种操作中选一个代价最小的（每种操作代价都是 1）：

    1. **插入 (Insert)**：在 `word1` 后面加一个字符。这相当于去匹配 `dp[i][j-1]`。

    2. **删除 (Delete)**：把 `word1` 最后一个字符删掉。这相当于去匹配 `dp[i-1][j]`。

    3. **替换 (Replace)**：把 `word1` 的字符换成 `word2` 的。这相当于去匹配 `dp[i-1][j-1]`。

**① 确定 dp 数组及下标含义**

**`dp[i][j]`**** 表示：将 ****`word1`**** 的前 **$i$** 个字符转换成 ****`word2`**** 的前 **$j$** 个字符所使用的最少操作数。**

**② 确定递推公式**

$dp[i][j] = \begin{cases} dp[i-1][j-1] & \text{if } word1[i-1] == word2[j-1] \\ \min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1]) + 1 & \text{if } word1[i-1] \neq word2[j-1] \end{cases}$

**③ dp 数组初始化**

第一行 `dp[0][j]`：把空字符串变成长度为 $j$ 的 `word2`，需要 $j$ 次插入。

第一列 `dp[i][0]`：把长度为 $i$ 的 `word1` 变成空字符串，需要 $i$ 次删除。

**④ 确定遍历顺序**

双层循环，从左到右，从上到下。

【99】31.下一个排列

想象一个数字序列，如果它是**全降序**的（如 `[5, 4, 3, 2, 1]`），它已经是最大的排列了。要找“下一个”，我们必须从后往前找，打破这种降序。

**第一步：寻找“转折点”（较小数）**

从后往前遍历，找到第一个**相邻升序**的对 `(i, i+1)`，即满足 `nums[i] < nums[i+1]`。

此时，`nums[i]` 就是我们要调换的“较小数”。

因为从 `i+1` 到末尾这一段已经是降序了，如果不动 `i` 左边的数，要把数字变大，非动 `nums[i]` 不可。

**第二步：寻找“接班人”（较大数）**

在 `nums[i]` 右侧的降序序列中，从后往前找，找到第一个比 `nums[i]` 大的数 `nums[j]`。

这个 `nums[j]` 就是我们要用来替换 `nums[i]` 的“接班人”。

**第三步：交换与反转**

1. **交换** `nums[i]` 和 `nums[j]`。

2. **反转** `i` 之后的所有数字。

    - 交换后，`i` 之后的部分依然保持着降序。为了让增量“最小”，我们需要把这一段变成升序（从小到大排），这样得到的数才是“下一个”。

**实例模拟：以 ****`[1, 2, 7, 4, 3, 1]`**** 为例。**

**找转折点**：从后往前，发现 `2 < 7`，所以 $i = 1$，`nums[i] = 2`。

**找接班人**：在 `[7, 4, 3, 1]` 中，从后往前找第一个比 `2` 大的数，发现是 `3`。所以 $j = 4$，`nums[j] = 3`。

**交换**：数组变为 `[1, 3, 7, 4, 2, 1]`。

**反转**：将索引 $i=1$ 之后的部分 `[7, 4, 2, 1]` 反转，变为 `[1, 2, 4, 7]`。

**最终结果**：`[1, 3, 1, 2, 4, 7]`。

【100】287.寻找重复数

这道题的**约束条件**极其严苛：

1. **不能修改数组**（排除掉排序、原地哈希）。

2. **只能使用 **$O(1)$** 的额外空间**（排除掉哈希表、集合）。

3. 数字范围在 $[1, n]$ 之间，数组大小为 $n+1$。

在这些限制下，这道题本质上是一道**链表找环**的问题，使用的是经典的 **Floyd 判圈算法（快慢指针 / 龟兔赛跑算法）**。

**我们可以把数组的下标 **$i$** 看作链表的节点，把数组的值 **$nums[i]$** 看作指向下一个节点的指针。**

由于存在重复的数字，这意味着有多个“指针”指向了同一个“节点”，这在逻辑上必然会形成一个**环**。环的入口，就是那个重复的数字。

**阶段一：找到相遇点（确认有环）**

定义两个指针 `slow` 和 `fast`，初始都指向 `nums[0]`。

**`slow`**** 每次走一步：**`slow = nums[slow]`。

**`fast`**** 每次走两步：**`fast = nums[nums[fast]]`。

当 `slow == fast` 时，说明它们在环内相遇了。

**阶段二：找到环的入口（找到重复数）**

将 `slow` 重新放回起点 `nums[0]`（或者定义一个新的指针 `finder` 指向 `0`）。

`slow` 和 `fast` 现在都以**相同的速度**（每次一步）移动。

它们**再次相遇**的地方，就是环的入口，也就是那个重复的数。
